    Writing a mission¶

    A mission file describes a flight the way a pilot would plan it: where it departs, then a list of phases (take-off, climbs, legs to waypoints, holding patterns, speed changes) in feet, knots and degrees. The simulator flies the plan smoothly, and the result becomes the truth that every Monte Carlo trial tries to follow. This page builds an example mission and explains how the simulator flies each part. The Mission YAML reference lists every key.

    Start from a copy¶

    Mission files are plain text in the YAML format. Open the app's trajectories folder (see User guide), copy bqn_departure.yaml or the example below to a new name, and edit it in any text editor. It appears in the app's Trajectory list the next time you open the list.

    Three rules of YAML matter here: indent with spaces, never tabs; start each list item, here each phase, with a dash; and anything after a # is a comment.

    An example: a training flight¶

    This half-hour flight from Rafael Hernández Airport (BQN) uses every kind of phase:

    name: BQN Training Flight

# A half-hour flight from Rafael Hernández Airport (BQN), Puerto Rico: climb
# to 8,000 ft, two turns in a holding pattern off the north coast, then a
# descent to 3,000 ft and a low-level leg east along the coast.

departure:
  lat_deg:  18.4949
  lon_deg: -67.1294
  alt_ft:   237.0              # runway elevation
  nav_bank_angle_deg: 25.0     # bank angle for the turns onto each leg

simulation_time:
  dt_s: 0.1                    # used only when a script gives no time step

phases:

  - type:           ground_roll  # from rest to lift-off speed
    heading_deg:    82.0
    run_length_m:   1800.0
    speed_final_kt: 150.0

  - type:        takeoff         # rotate to 10° pitch while accelerating
    heading_deg: 82.0
    pitch_deg:   10.0
    speed_kt:    220.0
    duration_s:  20.0

  - type:           climb        # straight ahead to cruise altitude
    pitch_deg:      8.0
    speed_kt:       220.0
    to_altitude_ft: 8000.0

  - type:     waypoint           # hold off the north coast
    lat_deg:  18.80
    lon_deg:  -66.70
    alt_ft:   8000.0
    speed_kt: 240.0
    loiter:
      n_turns:        2
      bank_angle_deg: 25.0
      direction:      left

  - type:         speed_ramp
    speed_end_kt: 280.0
    duration_s:   30.0

  - type:     waypoint           # descend to 3,000 ft on the way
    lat_deg:  18.75
    lon_deg:  -66.20
    alt_ft:   3000.0

  - type:     waypoint           # low-level leg east along the coast
    lat_deg:  18.55
    lon_deg:  -65.80
    alt_ft:   3000.0

    The file has four parts:

    • name is for your reference; the app lists missions by file name.
    • departure is the starting point, on the runway, and the bank angle for the turns onto each leg. The runway elevation is in feet above mean sea level.
    • simulation_time holds a time step that only a Python script uses, and only when it gives no time step of its own. The app and the command line always use their own setting.
    • phases lists the flight, in order. Each phase starts where the previous one ended, with its position, heading, speed and altitude.

    The phases¶

    Phase What the aircraft does
    ground_roll Accelerates from rest along the runway heading, reaching speed_final_kt after run_length_m metres. Every mission starts with one, and only one.
    takeoff Pitches up from level to pitch_deg over duration_s seconds, on heading_deg, while the speed changes to speed_kt. Give it the runway heading.
    climb Climbs straight ahead at speed_kt, at a flight-path angle of pitch_deg, to to_altitude_ft. If the target is lower, it descends at that angle instead.
    waypoint Turns toward the fix at lat_deg, lon_deg, then flies straight to it, climbing or descending steadily to alt_ft on the way. speed_kt sets the leg's speed; without it the aircraft keeps its current speed. An optional loiter block then flies n_turns full circles at bank_angle_deg, to the right (the default) or left.
    speed_ramp Changes speed steadily, over duration_s seconds, to speed_end_kt or to the Mach number speed_end_mach, keeping heading and altitude.

    A Mach number is converted to a speed with the speed of sound of the International Standard Atmosphere at the altitude of the last climb or waypoint: Mach 0.8 at 15,000 ft is 501 kt.

    Check a mission before running it¶

    The quickest check is in the app: run 2 trials at a 1 s time step and look at the 3D Trajectory and Map tabs. The log also reports the mission's length and duration.

    For more detail, this script flies a mission and reports its duration, distance, limits, and how close the track passes each waypoint:

    """Checks a mission before a Monte Carlo run: how long, how far, how close to each waypoint."""

from pathlib import Path

import numpy as np
import yaml

from ins_sim.core.earth_model import wgs84_radii
from ins_sim.trajectory.kinematics import build_trajectory

MISSION = Path(__file__).parent / "missions" / "training_flight.yaml"
FT, KT, NM = 0.3048, 0.514444, 1852.0

truth, _, _ = build_trajectory(str(MISSION), tau_i=1.0)

speed = np.linalg.norm(truth.v_eb_n, axis=1)
flown = np.sum(np.linalg.norm(np.diff(truth.r_lb_l, axis=0), axis=1))
print(f"Duration           {truth.t[-1] / 60:7.1f} min")
print(f"Distance flown     {flown / NM:7.1f} nmi")
print(f"Highest altitude   {truth.h_b.max() / FT:7.0f} ft")
print(f"Top speed          {speed.max() / KT:7.0f} kt")
print(f"Steepest bank      {np.rad2deg(np.abs(truth.euler_nb[:, 0])).max():7.1f} deg")
print(f"Steepest pitch     {np.rad2deg(np.abs(truth.euler_nb[:, 1])).max():7.1f} deg")

# How close the track passes each waypoint, from the latitude and longitude
# differences converted to metres with the WGS-84 radii of curvature.
with open(MISSION, encoding="utf-8") as fh:
    waypoints = [p for p in yaml.safe_load(fh)["phases"] if p["type"] == "waypoint"]
for n, wp in enumerate(waypoints, start=1):
    L_wp, lambda_wp = np.deg2rad(wp["lat_deg"]), np.deg2rad(wp["lon_deg"])
    R_N, R_E = wgs84_radii(L_wp)
    north = (truth.L_b - L_wp) * R_N
    east = (truth.lambda_b - lambda_wp) * R_E * np.cos(L_wp)
    k = np.argmin(np.hypot(north, east))
    print(f"Waypoint {n}: passes {np.hypot(north[k], east[k]) / 1000:4.1f} km away "
          f"at {truth.t[k] / 60:4.1f} min, at {truth.h_b[k] / FT:5.0f} ft "
          f"(planned {wp['alt_ft']:.0f} ft)")

    For the training flight it prints:

    Duration              27.0 min
Distance flown       112.7 nmi
Highest altitude      8030 ft
Top speed              280 kt
Steepest bank         25.0 deg
Steepest pitch         8.9 deg
Waypoint 1: passes  0.1 km away at 14.6 min, at  8030 ft (planned 8000 ft)
Waypoint 2: passes  3.0 km away at 21.2 min, at  3433 ft (planned 3000 ft)
Waypoint 3: passes  0.8 km away at 26.9 min, at  3037 ft (planned 3000 ft)

    The aircraft passes right over the first waypoint, where its holding pattern starts, and within a kilometre of the last one. It misses the second by 3 km, for a reason the next section explains. The altitudes are 30 ft high because of the 1 s time step; at 0.1 s they are within a few feet.

    How the simulator flies a plan¶

    The simulator turns the plan into a smooth flight that obeys the laws of motion, rather than one that passes exactly through every point:

    • Turns. The aircraft turns onto each leg at the departure's nav_bank_angle_deg, in a coordinated turn: the bank angle follows from the speed and the turn rate, and there is no sideslip.
    • Waypoints are approached, not hit. The bearing and distance to a waypoint are worked out from where the previous phase ended, before the turn onto the leg. The turn moves the aircraft sideways, so after a large turn the leg runs parallel to the planned one, offset by up to the turn's diameter: about 9 km at 280 kt and 25° of bank. The leg is then flown at a constant heading, which drifts from the great circle on long legs, by about 11 km over 1,000 km. On the packaged mission the track passes 3.5 to 5.6 km from each waypoint. To pass closer, add an intermediate waypoint so that the turn before the final leg is small.
    • Climbs and descents on a leg are steady. A waypoint leg changes altitude at a constant angle, set by the leg's length. A short leg with a large altitude change therefore makes a steep climb or dive: a 3° descent needs about 19 km for every 1,000 m.
    • Speed changes belong in a speed_ramp. A waypoint's speed_kt takes effect at the end of its turn, so a large change there is abrupt.
    • Transitions are smoothed. The velocity is smoothed over about two seconds, so the bank and pitch change over a few seconds at every phase boundary, as in a real aircraft.
    • Altitudes are close, not exact. Each change of phase can leave the altitude off by up to one time step's worth of climb: a few tens of feet at a 1 s time step, a few feet at 0.1 s.
    • What is not modelled. There is no wind, no angle of attack (the pitch equals the flight-path angle) and no sideslip. Heights are measured from the WGS-84 ellipsoid, and the departure elevation is used as such, since ins_sim has no geoid model.

    The Truth trajectory & ideal IMU page explains how the flown plan becomes the truth and the perfect IMU outputs.

    When a mission fails to load¶

    A mission that does not appear in the Trajectory list either has a YAML syntax error (often a tab, or a missing colon or dash) or has no phases section. Browse… says so when you pick it.

    A mission that appears but has a mistake stops the run with a Simulation failed message:

    Message Cause
    ValueError: The first phase must be a 'ground_roll'... The first phase is something else, or the phases are out of order.
    ValueError: Only the first phase can be a 'ground_roll' A second ground_roll: there is only one take-off run.
    ValueError: Unknown phase type: 'clmb' A misspelt phase type.
    KeyError: 'speed_kt' A phase lacks a required key, here speed_kt. The reference lists each phase's keys.
    ValueError: speed_end_mach needs an earlier 'climb' or 'waypoint' phase... A Mach speed_ramp before any phase has set the altitude.
    KeyError: 'simulation_time' The simulation_time section is missing.
